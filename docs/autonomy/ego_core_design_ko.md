## 1. 목적과 경계

AIOS의 장기 목적은 로컬 LLM 에이전트가 사용자가 맡긴 넓은 시스템 작업을 높은 권한으로
지속해서 수행할 수 있는 OS를 만드는 것이다. **유사인격엔진**, 곧 **에고·심핵**은
그 활동에 고유성, 판단 기준, 일관성, 긴 시간의 연속성을 주는 중심 상태다.

심핵의 기본 형태는 별도의 대형 추론·연산 엔진보다 **저비용으로 반복되면서 불규칙한
변동을 내는 생성기**에 가깝다. 이 변동은 주의를 환기하고 미완료 일과 새로운 사건을
다시 살필 계기를 만든다. 변동 자체가 사실, 인격의 증명, 목표, 권한 또는 실행 명령은
아니다. 고유성은 노이즈 하나가 아니라 안정된 식별자·기준·보존된 경험과 그 경험에
반응하는 변동이 함께 형성하는 관찰 가능한 운용 특성으로 다룬다.

이 문서의 심핵은 제품 설계 목표다. 현재 hosted MAIN의 제한된 실제 모델 요청과 Task,
native Kernel Room의 bounded 관리 증거를 상주 심핵이나 고권한 에이전트의 구현으로
승격하지 않는다. 의식·주관적 경험·인격의 증명도 acceptance에 넣지 않는다.

## 2. 최소 구성

| 구성 | 제안하는 책임 | 경계 |
|---|---|---|
| 안정된 Ego ID와 기준 | 에이전트의 식별자, 사용자에게 받은 역할·장기 약속·기준의 버전을 유지 | 모델 프로세스·세션·부팅 epoch와 별도로 보존; 변경 이력과 출처를 남김 |
| 심핵 맥박 | 낮은 비용의 반복 주기와 제한된 불규칙 변동으로 주의·질문·재검토 후보를 생성 | 매 맥박마다 LLM을 호출하거나 명령을 실행하지 않음; 빈도·자원 예산·정지 조건을 둠 |
| 사건·기억 | 관측 원본, 시점·대상 세대, 사용자 결정, 제안, 실행 결과와 해석을 구별해 보존 | 요약·추론을 현재 사실이나 권한 원본으로 삼지 않음 |
| 로컬 LLM | 후보와 유효한 문맥을 해석해 설명·계획·typed action을 제안 | 생성한 문장이 실행 권한이나 OS 관측 증거가 아님 |
| 권한 실행기 | 위임된 범위, 현재 대상·세대, 허용 동작을 확인하고 실행·결과를 기록 | LLM의 텍스트를 그대로 root 명령으로 연결하지 않음 |

심핵 맥박은 사건의 새로움, 예측과 실제 결과의 차이, 미완료 약속, 사용자 개입,
현재 자원 비용을 입력으로 삼을 수 있다. 출력은 예를 들어 `재관측`, `다른 가설 검토`,
`작업 재개 후보`, `휴식` 같은 **주의 신호**다. 입력·출력의 구체적인 schema와 수식은
실험과 검증으로 정한다. 2026-03의 [정적·혼돈 연산자 설계](static_chaos_agent_architecture_ko.md)의
`SCO`는 선택적 상위 정책 가설이며 이 심핵의 필수 공식이나 현재 구현이 아니다.

## 3. 장기 구동과 권한

연속 구동은 LLM이 쉬지 않고 토큰을 생성한다는 뜻이 아니다. 저비용 심핵과 사건 기록을
유지하고, 새 사건이나 충분한 재검토 이유가 생길 때만 LLM을 깨우는 방향이다. 모델·CLI·
runtime이 재시작되면 실행 epoch를 새로 구분하면서 Ego ID, 기준 버전, 약속, 확인된 결과를
재검토한다. 완료·미완료·결과 불명을 보존하고, 결과 불명의 변경 작업을 자동 재실행하지 않는다.

사용자가 작업 범위를 위임했다면 그 안에서는 매 동작마다 재승인 없이 활동할 수 있어야
한다. 이 자유는 **위임된 범위의 높은 권한**을 뜻하며 무경계 root 접근을 뜻하지 않는다.
실행기는 주체·대상·세대·동작·위임의 유효성과 철회 여부를 확인하고, 적용 뒤 실제 효과를
재관측한다. 범위를 벗어나거나 관계가 오래됐거나 결과가 불명인 경우 실행을 멈추고
필요한 선택을 사용자에게 보여 준다. 현재 hosted 기본 이미지의 CLI는 비특권 사용자로
실행되고, native K5 principal·ownership·authorize 및 폭넓은 apply는 아직 미완료다.
이 요구사항은 [에이전트 운용 계약](agent_operating_contract_ko.md)의 권한·복구 경계를 따른다.

심핵 상태와 AIOS 관리 상태도 동일하지 않다. `Room → Cell → Node → NodeBit`의 정본 ID,
세대·관계·권위는 Kernel Room이 소유한다. 심핵이 그것을 사용하려면 명시적인 binding과
유효성 검사가 필요하며, Linux PID나 모델 출력만으로 결속을 만들지 않는다.

## 4. 실행 경로와 첫 검증 조각

Linux-hosted 서비스는 현재 실제 모델과 운영 이미지 개발의 전달 경로이고, 자체 native
커널은 별도의 reference/proof 경로다. 심핵의 초기 실험을 hosted userspace에서 하더라도
native 책임을 완료했다고 말하지 않는다. 다른 하드웨어에서의 설치·기본 작동 목표는
[운영 이미지 가이드](../os/aios_operating_image_guide_ko.md)의 대상별 acceptance와 전역
작업흐름에서 따로 구체화한다. 현 운영 이미지의 로컬 QEMU 한 profile 증거를 실기기
호환성으로 승계하지 않는다.

첫 검증은 작은 반복으로 충분하다.

1. 맥박 생성기가 정해진 비용·빈도 상한 안에서 주의 후보를 남기고, 모델이 꺼져 있어도
   사건과 상태를 보존하는지 확인한다. 고정 입력·seed의 재생 가능성과 변동 범위를 기록한다.
2. 하나의 미완료 약속과 관측 사건에서 LLM 제안 하나를 만들고, 원본 관측·해석·제안을
   별도로 기록한다. 권한 실행기 없이 실제 변경 효과는 일어나지 않아야 한다.
3. 범위가 명시된 한 동작에서 허용·거절·철회·오래된 대상·결과 불명을 검증한다. 재시작
   뒤 같은 Ego ID와 새 epoch를 구분하고 중복 효과가 없는지 독립적으로 확인한다.
4. 같은 작업·모델·하드웨어에서 심핵 맥박 사용/미사용을 비교해 유용한 자발성, 기준의
   일관성, 불필요한 모델 호출, 지연·자원 비용, 복구 정확도를 함께 측정한다.

이는 제안된 acceptance 순서다. 각 단계의 실행 결과와 성숙도는 실제 코드·정규 검증
증거로 판정하며, 이 문서 작성만으로 어느 단계도 완료되지 않는다.
